# F-03: Prompt assembly & context fragments

> Status: implemented
> Priority: P0
> Source evidence: codex-rs `core/src/context/*` (world-state and
> environment-context fragments, model-switch fragment, token-budget
> fragments), `core/src/context_manager/history.rs` (world-state baseline and
> diffing), `core/tests/suite/model_switching.rs`

## Summary

Every accepted agent run freezes a **semantic run prompt**: a typed, ordered
set of prompt blocks that never changes for the lifetime of the run. The
blocks carry instruction, context, catalog, and environment content, each
with an authority, a trust label, a stable source identity, and a cache
scope. This feature defines the fragment catalog breadth for the frozen
prompt: a **world-state fragment** (durable run facts: session, agent
instance, operation, run kind, model), an **environment-context fragment**
(host facts: OS, architecture, shell, hostname, timezone, locale), and a
**model-switch fragment** (a factual notification when the model executing a
session changed since the previous turn).

## Problem

A coding agent needs to know more than its instructions to behave correctly:
it needs its own durable identity (which session, which agent instance,
whether it is resuming prior work, which model is executing), the shape of
the machine it runs on (OS, shell, architecture — because commands and paths
differ across platforms), and when its own model changed mid-conversation
(so it can interpret prior context produced by a different model). Without
explicit, typed fragments for these facts, the model either guesses, or the
run prompt mixes environment details with instructions, and cache scoping
becomes impossible to reason about.

piko already freezes a per-run prompt with platform policy, operator
settings, project context files, skills and prompt-template catalogs, agent
instructions, and a minimal date/cwd environment block. Three fragment
classes are missing: durable run identity (world state), host environment
facts beyond date/cwd, and the model-switch notification.

## User journeys

1. A user starts a fresh session. The run's frozen prompt contains a
   world-state fragment stating the session/agent/operation identity, the
   run kind (`initial`), and the model in use, plus an environment-context
   fragment describing the host (OS, architecture, shell, hostname, timezone,
   locale). No model-switch fragment appears because there was no previous
   turn.
2. The user switches the default model and submits another message. The new
   run's frozen prompt contains a model-switch fragment stating the previous
   model and the current model, so the new model treats prior context as
   generated by a different model.
3. The user resumes a session after hostd restarts. The world-state fragment
   marks the run as a continuation of prior work, and run facts (session,
   agent instance, operation) let diagnostics and multi-agent supervision
   attribute output to the correct run.
4. A tool runs on macOS with zsh. The environment-context fragment tells the
   model `os: macos`, `arch: aarch64`, `shell: /bin/zsh`, so command
   construction matches the host.

## In scope

- A world-state fragment carrying durable run facts: session id, agent
  instance id, operation (turn) id, run kind (`initial` vs `continuation`),
  and the model id executing the run.
- An environment-context fragment carrying host facts: OS, architecture,
  shell, hostname, timezone, and locale, from a whitelisted capture that
  never includes full process environment or secrets.
- A model-switch fragment emitted only when the model for a session changed
  between turns, stating the previous and current model ids.
- Correct block typing (authority, trust, source, cache scope) so the new
  fragments stay out of the stable cache prefix.
- Fragment capture and assembly stay deterministic: stable key order, stable
  block ids, and identical output for identical inputs.

## Out of scope

- World-state *diffing* across turns (emitting only what changed). This slice
  freezes a full snapshot per run; diffing belongs to the F-04 context
  management workstream.
- Inter-agent message fragments (F-10 v2 collaboration surface) and
  token-budget/rollout-budget fragments (M1).
- Mention-syntax parsing and general prompt-debug tooling.
- Provider-level cache-planning policies beyond the existing scope labels.
- Model-switch detection for subagents spawned mid-run with a per-agent model
  override; the slice covers session-level model continuity for hostd runs.

## Behavior and states

### Block catalog

The frozen per-run prompt is assembled from this catalog (in emission order):

| Block id | Kind | Authority | Trust | Source | Cache scope |
|---|---|---|---|---|---|
| `platform.policy` | Instruction | Platform | Trusted | `compiled` / `piko/platform-policy` | GlobalStable |
| `operator.settings` | Instruction | Operator | Trusted | `settings` / `host/operator-prompt` | OperatorStable |
| `agent.instructions` | Instruction | Agent | by provenance | agent provenance | AgentStable |
| `project.context.*` | Instruction | Project | WorkspaceControlled | `workspace-file` / path | ResourceSnapshot |
| `catalog.skills` | Catalog | None | WorkspaceControlled | `workspace-catalog` / skills | ResourceSnapshot |
| `catalog.prompt-templates` | Catalog | None | WorkspaceControlled | `workspace-catalog` / prompt-templates | ResourceSnapshot |
| `environment.host` | Environment | None | Trusted | `environment` / `host` | RunDynamic |
| `environment.run` | Environment | None | Trusted | `environment` / `accepted-run` | RunDynamic |
| `context.model-switch` | Context | None | Trusted | `environment` / `model-switch` | RunDynamic |

The blocks (`environment.host`, `context.model-switch`) are RunDynamic and
therefore never participate in the stable cache prefix; a change in host
facts or model never invalidates cached platform/operator/agent/resource
segments.

### World-state fragment

**Superseded by F-04 slice 2 (world-state diffing, [D-17](../design/D-17-world-state-diffing.md)).**
The run identity facts are no longer a frozen prompt block: hostd emits them
as a retained transcript Context message that is injected full on the first
run and diffed across subsequent runs. The fact set and line format below
remain the full-snapshot content contract.

The fact set, in fixed key order with one line per available fact:

```text
session_id: <id>
agent_instance_id: <id>
operation_id: <turn id>
run_kind: initial | continuation
model: <model id>
```

- `run_kind` is `continuation` when the session already has committed
  entries or turns before this run; otherwise `initial`.
- Missing facts are omitted; values are never fabricated.
- Empty/blank values are treated as absent.

### Environment-context fragment (`environment.host`)

Emitted when the host capture yields at least one fact. Content is a fixed
key order:

```text
os: <os>
arch: <arch>
shell: <shell path>
hostname: <hostname>
timezone: <UTC offset>
locale: <locale>
```

- Capture reads only whitelisted sources: `std::env::consts::OS`,
  `std::env::consts::ARCH`, and the `SHELL`, `HOSTNAME`/`COMPUTERNAME`,
  `LANG`/`LC_ALL` environment variables; timezone is the local UTC offset.
- Unavailable facts are omitted; no process environment or credentials are
  ever included.

### Model-switch fragment (`context.model-switch`)

Emitted only when the previous model for the session and the current model
are both known and differ. Content is a factual statement:

```text
<model_switch>
The model in use changed since the previous turn. Prior turns ran on
"<previous model>"; this run executes on "<current model>". Treat prior
context as generated by a different model.
</model_switch>
```

- First run (no previous model): absent.
- Model unchanged: absent.
- Model unknown (no configured default): absent.

### States

- **Empty capture**: fragments with no available facts are omitted entirely.
- **Determinism**: identical inputs produce byte-identical blocks, digests,
  and cache segments; fragment key order is fixed.
- **Cache safety**: all three new blocks are RunDynamic, so their presence
  and content do not change `semantic_prefix_digest`.
- **Assembly version**: the semantic-prompt assembly version bumps when the
  block catalog shape changes, so old frozen prompts are not replayed as new.

## Acceptance criteria

- [ ] **Superseded (F-04 slice 2)**: the run facts are emitted as a retained
      transcript Context message (full on first run, diff after), not as a
      frozen `state.run` block; see F-04 slice 2 acceptance criteria.
- [ ] A hostd snapshot with host facts emits exactly one `environment.host`
      block with the captured facts in the fixed key order, and omits
      unavailable facts.
- [ ] A hostd snapshot with no host facts emits no `environment.host` block.
- [ ] A run whose previous model differs from the current model emits exactly
      one `context.model-switch` block naming both models; first runs and
      unchanged-model runs emit none.
- [ ] The RunDynamic blocks (`environment.host`, `context.model-switch`)
      never change
      `semantic_prefix_digest`; a change in project context still does
      (regression guard).
- [ ] Identical inputs produce identical `environment.host` and
      `context.model-switch` block content and digests (determinism).
- [ ] The world-state full-snapshot content marks `run_kind: continuation`
      for a continued session and `run_kind: initial` for a fresh one
      (unit-tested in F-04 slice 2).
- [ ] Differential validation: the model-switch fragment appears in the
      second turn of a two-turn model change and states both model ids,
      mirroring the codex-rs `model_change_appends_model_instructions_developer_message`
      fixture shape.

## Product decisions

| Question | Decision | Rationale |
|---|---|---|
| What goes in world state? | Durable run facts only (session/agent/operation/model, run kind), not derived instructions | Keeps identity stable per run and diffable in M1 |
| Where do host facts come from? | Whitelisted capture (consts + `SHELL`/hostname/locale/timezone) | Fail-closed: never dumps process env or secrets |
| When is model-switch emitted? | Only on a known previous→current model change | Avoids noise on first run and unconfigured models |
| Which cache scope for the new fragments? | `RunDynamic` for all three | Host/run facts change without invalidating stable prefix segments |
| Are fragments optional? | Yes, omitted when no facts are available | Keeps tests and minimal setups stable; no fabricated values |

## Fusion decisions (codex-rs)

| codex-rs behavior | Decision | piko landing / rationale |
|---|---|---|
| `WorldStateSnapshot` with baseline diffing across turns | **kept (adapted)** | piko landed in F-04 slice 2 (D-17): full snapshot as a retained transcript Context message on the first run, diff messages afterwards, hostd-owned durable baseline cleared on compaction |
| `EnvironmentContext` XML injected as a model-visible message | **kept (adapted)** | piko emits a typed `environment.host` block in the frozen prompt instead of an XML message; same model-visible facts |
| `<model_switch>` developer message on model change | **kept (adapted)** | piko emits a `context.model-switch` block from hostd session continuity; wording is piko-native, not codex text |
| ~30 fragment modules (token budget, guardian reminders, inter-agent, realtime, ...) | **rejected (deferred)** | Each lands with its owning feature (M1, F-11, F-10, F-16); no 1:1 module parity |

## Open questions

1. Should `environment.host` eventually move into the stable cache prefix
   with a per-session key? Deferred; RunDynamic is safe and simple.
2. Should model-switch handle subagent per-agent model overrides? Deferred to
   the F-10 roles slice, which will own per-agent model resolution.
